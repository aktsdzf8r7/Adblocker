# Verdornt – Etappe 1 „Ankunft“ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a playable first stage of the New Horizons mod `Zeki.Verdornt`:
- the crashed seed on Timber Hearth,
- the crossing into the system Dornenkranz and back home,
- Erstling, fully explorable,
- the other four bodies as exteriors,
- dimensions 1–4,
- the Ausguck with its system projection,
- marble tubes and reactive computers.

**Architecture:** Same pattern as `Zeki.ISAE`:
- Blender (`tools/verdornt_models.py`) builds the meshes and `anchors.json`.
- A Python build script turns the anchors into NH configs and `placements.json`.
- A C# DLL (`ZekiVerdornt.dll`) loads the OBJ models and adds what NH cannot do: changing systems, marble tubes, reactive computers and real Dark Bramble vines.

**Tech Stack:**
- Blender 4.2 (headless) and Python 3 with Pillow.
- New Horizons JSON/XML configs.
- C# netstandard/net48 against OWML 2.15.5 and OuterWildsGameLibs 1.1.16.1372.
- dotnet 8 SDK.

**Spec:** `docs/superpowers/specs/2026-10-10-verdornt-design.md` (sections 2–5, 7, 8; stage 1 in section 9)

## Global Constraints

- **Game and dependencies:** base game only, no EotE content. Dependencies are only `xen.NewHorizons` and OWML 2.15.5.
- **Naming:**
  - Mod uniqueName `Zeki.Verdornt`, DLL `ZekiVerdornt.dll`, C# namespace `ZekiVerdornt`.
  - Condition prefix `ZEKIVD_`.
  - Ship-log IDs prefix `ZEKIVD_`.
- **Star system:** NH system name `Verdornt`.
- **Body names:** `Herzdorn`, `Erstling`, `Glutdorn`, `Nebelranke`, `Hohlsamen`, `Ausguck`. Dimension names as in the spec table, without umlaut problems. They are ASCII-safe: `Ankunftskammer`, `Eispforte`, `Splittergang`, `Kaeltenest`, `Samenschlund`.
- **Language:** All player-facing text is German. Code and comments are English.
- **Texts:** Nomai text lines are short. Yarrow lines are marked in the generator, but Yarrow does not appear in stage 1 texts except as one harmless line (spec 3.1).
- **Props:** Props that exist in the game are copied from the game (NH details). Everything else is a Blender model.
- **Do not break the other mods:** `Zeki.Schleiersystem` must rebuild byte-identically. `Zeki.ISAE` validates with 0 errors and is otherwise untouched, except for shared tools that stay backwards compatible.
- **Quality bar:**
  - `nh_validate.py` with 0 errors and 0 warnings for all three mods.
  - `dotnet build -c Release` with 0 warnings.
  - All OBJ files have consistent winding.
- **Loop:** Time loop is enabled in `Verdornt` (22 min). `respawnHere`/`startHere` are false, so death wakes the player on Timber Hearth.

## Review Focus

- **Re-entering the vortex:** Re-entering the Samenschlund vortex while a system change is already running must not trigger a second change. Guard it with a flag and test it.
- **Rücksamen and death:** Using the Rücksamen right as the player dies must not change system twice. Ignore the interaction while the player is dying.
- **Marble dropped between slots:** It must roll to the nearest slot or back to its rest slot, never off the tube path. A unit test over the path projection covers this.
- **Reactive computers:** When several states are true at once, exactly one is visible: the highest priority. The C# selection function is pure and gets a test via a tiny test project.
- **Loading the same save in SolarSystem:** Loading a save that already has `ZEKIVD_ERSTE_REISE` set must still spawn the player normally on Timber Hearth. The arrival effect only runs after a crossing.

### Task 8: Marble tubes, gate, warp tower, Ausguck

**Files:**
- Create: `Zeki.Verdornt.Source/Logic/TubePath.cs`, `Zeki.Verdornt.Source/MarbleTube.cs`, test `Zeki.Verdornt.Tests/TubePathTests.cs`
- Modify: `tools/verdornt_build.py`

**Interfaces:**
- Produces:
  - `TubePath` (pure, `System.Numerics.Vector3`):
    - constructor `(IReadOnlyList<Vector3> points)`
    - `float Length`, `Vector3 At(float s)`
    - `float Project(Vector3 p)` → arc length of the nearest point
    - `int NearestSlot(float s, IReadOnlyList<float> slots)`
  - `MarbleTube : MonoBehaviour`:
    - The marble visual is the mesh and material of any `NomaiInterfaceOrb` found in the scene, with a Blender sphere as fallback.
    - The player aims at the marble and holds interact; the marble follows the projection of the view ray onto the path at max 4 m/s.
    - On release it rolls to `NearestSlot`. Entering slot X sets persistent condition `ZEKIVD_<TUBE>_<SLOT>`, and the tube's actions react to it.
- Actions in stage 1:
  - `tor/offen` → move `lager_tor` up 6 m over 3 s.
  - `turm_erstling/wach` → NH warp transmitter `ZEKIVD_WARP_AUSGUCK` activates (detail container with `activationCondition`).
  - `lift_ausguck/oben` → `ausguck_lift` moves between two anchors.
- Ausguck content:
  - NH remote `ZEKIVD_SYSTEM`: platform at `ausguck.becken`, stones in the camp (`lager.stein1`) and next to the Erstling tower.
  - NH warp receiver for the Ausguck, and a transmitter back.

- [ ] **Step 1:** Write the tests:

  - `NearestSlotRoundsToClosest`: slots [0, 6, 10], s=7.5 → 1.
